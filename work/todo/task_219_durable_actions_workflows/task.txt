Task 219 - Durable Actions workflows and task-aware playback

Goal
====

Turn the current development recorder into a useful, inspectable workflow
system without creating a second editor or hiding agent activity.

Parent goal
===========

[`architecture/goals/AGENT_NATIVE_CREATIVE_RUNTIME_TARGET.md`](../../../architecture/goals/AGENT_NATIVE_CREATIVE_RUNTIME_TARGET.md)

Depends on
==========

- [`Task 215`](../../done/task_215_shared_command_schemas_and_examples/task.txt) for
  schema-driven property editing and examples.
- [`Task 217`](../task_217_ui_actions_mcp_equivalence_harness/task.txt) for
  shared-route equivalence evidence.

Required work
=============

- Add named Action sets/actions with deterministic ordering and selection.
- Persist a versioned bounded format with migration/incompatibility reporting.
- Build property editing from shared schemas, not command-specific React logic.
- Support user-named variables and explicit target/result bindings.
- Add play action, play from step, play step, stop and clear result states.
- Await supported async tasks, show progress/cancellation and fail closed on
  timeout or missing result artifacts.
- Define ordinary stepwise history versus explicitly atomic playback.
- Show origin, parameters, results, duration, errors and a short optional
  user-facing rationale; never persist private model reasoning.
- Keep recorder/action size, nesting and payloads bounded.

Definition of done
==================

- A named multi-step workflow survives restart and replays on a fresh document
  using stable bindings.
- Async and rejected steps have understandable visible outcomes.
- Playback does not record itself and normal UI behavior remains unchanged.
- The saved format and migration behavior are tested but not declared 1.0-stable.

Non-goals
=========

- Teach mode or automatic skill parameterization.
- A parallel Actions-only mutation implementation.

Current evidence (2026-08-20)
=============================

- [`Task 271`](../../done/task_271_durable_action_sets/task.txt) delivered the
  durable named-set storage, panel controls, migration and restart proof.
- Concrete stopped Actions can be user-named, explicitly saved, loaded and
  deleted from a deterministic bounded library.
- The version-3 envelope groups at most 32 Actions into at most 16 stable named
  Action Sets, with 256 steps per Action, 2 MiB per Action and 8 MiB total.
  Set/action ordering and selection are deterministic; malformed,
  newer-version, unknown-command, non-replayable and oversized content fails
  atomically.
- Every recorded step stores its command-contract status and schema version.
  Existing version-1 and version-2 flat libraries migrate atomically into the
  stable Default Set after validating current complete-schema inputs, completed
  results and recorded result bindings. Incompatible libraries stay unloaded
  with a precise error; playback repeats the contract preflight before
  executing its first step.
- Desktop persistence is host-owned and atomically written under app userData;
  it does not depend on the renderer's changing localhost origin. Web uses its
  browser-origin storage adapter.
- Loaded document-scoped steps retarget to the active document while stable
  inter-step result bindings remain intact. Playback remains recording-isolated.
- Play Step and Play From Here now compute the minimal transitive producer set
  for stable result bindings and created/duplicated document identities. A
  packaged Duplicate -> Create Layer Action started at step two, replayed the
  required fork first and edited the fresh result document.
- A packaged two-process smoke creates and renames sets, stores the same
  two-step recording independently in two sets, fully restarts the app, proves
  selected-set and filtered-action persistence, replays the original Action and
  verifies that deleting one set deletes only its contained Action.
- Accepted async commands now replay through subscribed document-task state,
  show progress, fail closed on missing/failure/cancel/timeout and support Stop
  through the real task owner. Completed export artifacts are available to
  later stable result bindings.
- User variables and explicit migration transforms for future command-schema
  versions remain open.
