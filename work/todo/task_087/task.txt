# Task 087 — diagnostics, privacy and support bundle (P0)

Priority: P0. Dependencies: none. Expected effort: 4–7 focused hours.

## Objective

Make failures supportable without exposing user documents, paths, tokens or
content. Produce one bounded diagnostic artifact a user can inspect before
sharing.

## Required work

- Define diagnostic schema for version/build, host, GPU adapter/features,
  document type/dimensions (not content), subsystem failures, timing summaries,
  owned-resource totals and recent bounded application events.
- Centralize redaction for paths, URLs, bearer tokens, pairing codes, document
  text, filenames when opted out and binary payloads.
- Add Copy summary and Export diagnostic bundle using the normal host save port.
- Include validity metadata; unavailable samples remain unavailable, never zero.
- Bound event count/bytes and avoid continuous telemetry or network upload.
- Document local-first privacy behavior and which optional remote AI/MCP paths
  transmit data.

## UI exposure

Add a Diagnostics section to the existing Debug/About experience with preview,
redaction choices, Copy and Export. Keep development-only controls separated.

## Verification and completion

- Secret/path/content canary tests prove redaction in JSON and attachments.
- Generate a bundle from PNG, PSD, PDF and a simulated renderer failure.
- Measure collection cost and prove it triggers no recomposition/readback.
- Run web/desktop tests and builds, update reliability/privacy docs, commit/move.
