Task 221 - Close semantic artist capability gaps

Goal
====

Implement the meaningful artist operations identified by Task 214 through the
existing application/document/history/render owners so normal UI, Actions and
MCP can share them. This is outcome-driven category migration, not wrapper
generation to increase a command count.

Parent program and goal
=======================

- [`Task 214`](../task_214_complete_action_command_mcp_coverage/task.txt)
- [`Agent-native creative runtime target`](../../../architecture/goals/AGENT_NATIVE_CREATIVE_RUNTIME_TARGET.md)

Execution method
================

Move one useful category/workflow vertically through:

```text
real UI operation
  -> semantic command/query/gesture owner
  -> schema and capability projection
  -> Actions record/play behavior
  -> reviewed MCP admission where appropriate
  -> equivalent state/history/render proof
```

Initial category order is chosen from Task 214 evidence and artist value, not
file size or easiest implementation. Expected domains include layer structure,
transforms, masks/selections, paint, text/vector completeness, adjustments and
Grade/Lens FX, assets/projects and generation placement.

Completed vertical slices
=========================

- layer structure and affine transforms;
- geometric and discrete selection state;
- bounded Brush/Erase commits without routing pointer updates through commands;
- targeted basic Grade mutations plus canonical queries;
- editable point text creation and discrete formatting;
- layer-mask add/remove/enabled/linked state, including selection-derived masks.
- native Rectangle/Ellipse/Triangle/Line creation observed after local commit.
- native open/closed Pen path creation and resumed-path updates observed after
  local commit, with previews kept outside command transport.
- native Add/Delete/Convert Point and Direct Selection geometry commits, with
  selection-only and preview work kept outside command transport.
- native Gradient Fill creation and on-canvas editing, including its layer role
  and presentation, plus raster/mask Gradient through its GPU/history owner.
- non-destructive Warp Push and held-mode commits, with local preview scheduling,
  bounded Actions replay and reviewed Agent/MCP execution plus recipe query.
- atomic solid raster/mask Fill through the existing GPU transaction and pixel-
  history owner, with explicit targets and rendered external MCP evidence.
- raster/mask pixel-gradient commit through the same GPU/history owner, with a
  shared gradient schema and local-only drag interaction.
- Dodge, Burn and Sponge final strokes with explicit snapshotted operator
  settings and local-only frame-scheduled interaction.
- Clone Stamp and Healing Brush final strokes with an immutable renderer-owned
  source snapshot and bounded document-relative source metadata for replay.
- Magic Wand sampled selection through its existing GPU/history owner, with
  newest-request, cancellation and stale-completion protections retained.
- native Path Text creation through `text.create`, with stable path references,
  packaged Actions replay and direct Agent/MCP creation/query.
- contextual fixed rotate/flip through `transform.applyFixed`, preserving the
  existing selection, mask, single-layer and layer-group transaction owner.
- explicit creation of every visible adjustment through `adjustment.create`,
  including local, attached and standalone adjustment-layer placements.
- explicit raster or mask inversion through `raster.invert` and its existing
  reversible GPU transaction.
- text finalization through `text.convertToShape` and `text.rasterize`, retaining
  stable layer IDs and the existing vector-path and GPU pixel-history owners.
- explicit contiguous layer merge, group flatten and document flatten through
  their existing full-canvas compositor and history owner.

Rules
=====

- Reuse existing controllers and canonical document operations.
- Preserve working UI semantics, undo boundaries and dirty-only rendering.
- Do not turn ephemeral panel state into a command without an agent/user need.
- Do not send raw high-frequency UI events through the command service.
- Do not admit a category to MCP before permissions, schemas and representative
  evidence are ready.
- Split category implementation further only when ownership or verification
  genuinely differs; smaller tasks are not an objective by themselves.

Definition of done
==================

- Task 214's inventory has no unexplained semantic capability gaps.
- Every implemented category has at least one representative complete artist
  flow, not merely isolated executor unit tests.
- Normal UI reaches the same owner and retains product behavior/performance.
- Unsupported or intentionally local-only operations remain explicit.
- Remaining target-only capabilities are documented as future product work,
  not hidden inside an inflated coverage percentage.
