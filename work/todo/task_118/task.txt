# Task 118 — Professional Face Warp: HQ implementation and USP path

Status: IN PROGRESS — NOT READY FOR NORMAL TOOLBAR USE

## Objective

Build Face Warp as a high-quality, non-destructive, offline and scriptable
portrait-geometry effect. Face Warp must use one source mesh and one target
mesh. Semantic controls, direct manipulation, the proportional brush, the GPU
image deformation and the debug overlay must all use that same target mesh.

The feature must not translate its canonical state into generic Warp strokes,
must not move the canvas outside the detected face/collar, and must not return
to the normal toolbar until the HQ gates below pass.

Primary architecture and research decisions:

- `architecture/research/LIGHTTABLE_FACE_WARP_ARCHITECTURE.md`

## Phase 2 — Single-truth indexed WebGPU renderer

- [x] Define a face-agnostic evaluated `DeformationSurface` contract containing
      source positions/UVs, target positions, indices, revisions and dirty
      ranges; no landmark indices may enter the generic renderer API.
- [x] Keep authoring topology pluggable: Face Warp emits its irregular canonical
      triangles, while a future screen-space Custom Warp can emit tessellated
      rectangular Bezier patches with user-inserted split rows/columns.
- [x] Create immutable source-position/UV and triangle-index GPU buffers.
- [x] Create a small dynamic target-vertex buffer.
- [x] Implement target-triangle rasterization with barycentric source sampling.
- [x] Keep full-resolution layer pixels on the GPU; no CPU pixel readback.
- [x] Add a pinned transition collar/cage around the face so moved jaw and
      hairline boundaries produce no holes, hard seams or duplicated pixels.
- [x] Make identity deformation pixel-identical to the unwarped input.
- [x] Feed the exact same evaluated target mesh into renderer and debug overlay.
- [x] Dirty only the Face Warp node/target buffer during interaction.

Gate 2 — first commit-worthy milestone:

- [x] A numbered checkerboard fixture deforms exactly with the target mesh.
- [x] Overlay vertices and rendered triangle corners agree within 0.5 screen px.
- [x] Identity RMSE is zero, or a documented format-rounding epsilon only.
- [x] No holes, folds, black pixels or canvas movement occur.
- [ ] Only after this gate may Face Warp return to the normal toolbar.
