Task 233 - Semantic Warp stroke commits
=======================================

Goal
====

Expose one completed non-destructive Warp stroke to Actions and reviewed MCP
execution while preserving the existing frame-coalesced local pointer path.

Contributes to
==============

- [`Task 214`](../task_214_complete_action_command_mcp_coverage/task.txt)
- [`Task 216`](../task_216_semantic_gesture_commit_and_performance/task.txt)
- [`Task 217`](../task_217_ui_actions_mcp_equivalence_harness/task.txt)
- [`Task 221`](../task_221_close_semantic_capability_gaps/task.txt)

Existing owner confirmed
========================

- `warpSessionController` already freezes document input into layer-source
  coordinates, frame-coalesces previews and creates one reversible history entry.
- The committed `WarpStroke` is a versioned non-destructive recipe in the
  raster layer adjustment stack; replay does not need pointer simulation.
- Push and held rate-based modes have different sampling semantics but converge
  on the same final stroke model.

Checklist
=========

- [ ] Define a bounded semantic Warp stroke contract using layer-source samples.
- [ ] Validate mode, brush settings, timing, sample count and payload bytes.
- [ ] Execute directly through the Warp document/stack owner without UI pointers.
- [ ] Observe exactly one final stroke after successful UI history commit.
- [ ] Keep move/moveMany, hold ticks and preview scheduling outside command transport.
- [ ] Preserve transformed-layer coordinate semantics and immutable stroke settings.
- [ ] Define stable result binding for layer and authored stroke id.
- [ ] Cover cancel, document switch, locked target and oversized payload failures.
- [ ] Record, undo and replay representative push and held-mode packaged Actions.
- [ ] Prove packaged Agent Access execution and query the stored Warp recipe.
- [ ] Measure frame submissions/history/recorded bytes without inventing a parity score.
- [ ] Run type, contract, boundary, full app and packaged regression gates.

Scope guard
===========

- No raw pointer events or per-frame previews cross Actions/MCP.
- No rasterized displacement snapshot is used as the replay source.
- Remote admission follows bounded schema and packaged evidence; the existing
  experimental Face Warp command is not evidence for this distinct tool.

Completion contract
===================

One real Warp gesture remains responsive, creates one history entry and records
one bounded semantic operation. Replay restores the same editable Warp recipe
on the explicitly targeted raster layer, including held-mode timing semantics.
