Execution tracker
=================

Each phase is implemented, tested and committed separately. A phase may only be
checked after its acceptance criteria have been verified in LightTable. Detailed
technical requirements remain authoritative in
`LIGHTTABLE_WEBGPU_OBJECT_SELECTION_MODELS.md`.

- [ ] Phase 1 - Establish and stabilize the SlimSAM baseline
  - [ ] Reproduce and remove the first-activation document-runtime failure.
  - [ ] Record cold initialization, image encode, point/box decode, GPU-memory
        and system-memory measurements separately.
  - [ ] Capture a fixed licensed/internal reference corpus covering opaque
        objects, hair, thin structures, low contrast, overlap and small objects.
  - [ ] Preserve current SlimSAM masks and measurements as comparison artifacts.
  - Acceptance: repeated activation/cancellation does not crash or create a
    recovery record, and the baseline is repeatable.

- [x] Phase 2 - Extend the model-neutral segmentation contract
  - [x] Represent positive and negative points, prompt history and optional
        previous-mask input without leaking model tensors into UI/tool code.
  - [x] Add explicit backend capabilities and model/preprocessing identity.
  - [x] Cover stale requests, aborts, candidate ownership and resource disposal.
  - [x] Keep SlimSAM functional through the extended contract.
  - Acceptance: focused contract/controller tests pass without a SlimSAM UX
    regression.

- [x] Phase 3 - Integrate SAM 2.1 Hiera Small FP16 experimentally
  - [x] Add the encoder/decoder behind the existing worker/backend boundary.
  - [x] Centralize repository revision, graph names and preprocessing metadata.
  - [x] Verify point and box coordinates, padding, unpadding and mask rescaling.
  - [x] Keep SlimSAM as a temporary internal fallback.
  - Acceptance: one image encode produces correctly aligned masks independent of
    zoom and device-pixel ratio, with explicit cleanup on close/switch.

- [x] Phase 4 - Complete cached iterative prompting
  - [x] Support click, Alt/Option-click, box drag, prompt undo and reset.
  - [x] Reuse image embeddings for prompt-only changes.
  - [x] Permit at most one decode in flight and retain only the newest pending
        hover point; stale results may never publish.
  - [x] Key cached embeddings by document/source revision, sampling mode, model,
        artifact revision, precision and preprocessing revision.
  - Acceptance: prompt refinement never reruns the encoder and repeated document,
    layer and tool switching leaves memory stable.

- [x] Phase 5 - Validate GPU preview and selection output
  - [x] Render temporary masks through the existing GPU overlay and dirty only
        that overlay during interactive preview.
  - [x] Commit through the normal LightTable selection representation and its
        New/Add/Subtract/Intersect compositor.
  - [x] Make cancel non-destructive and prevent history/undo races.
  - Acceptance: overlay updates do not recompose the document and confirm/cancel
    behave like the other selection tools.

- [ ] Phase 6 - Benchmark SAM 2.1 against SlimSAM
  - [ ] Measure initialization, encoder/decoder p50/p95, peak GPU/system memory,
        IoU, boundary score, thin-structure retention and prompt stability.
  - [x] Perform visual review of the fixed corpus in addition to numeric scoring.
  - [x] Record the evidence for retaining or promoting SAM 2.1 Small as default.
  - Acceptance: SAM 2.1 Small is promoted only when it measurably and visibly
    improves real LightTable cases without unacceptable latency or memory cost.

- [ ] Phase 7 - Add LightTable-owned high-resolution boundary refinement
  - [ ] Restore the soft mask to source/document coordinates.
  - [ ] Build an uncertainty band and run edge-aware refinement against the
        original full-resolution image on the GPU where appropriate.
  - [ ] Preserve soft edges and avoid halos, holes and zoom-dependent output.
  - Acceptance: boundary-heavy cases improve measurably while preview remains
    interactive and avoids a full CPU/GPU image roundtrip.

- [ ] Phase 8 - Productize model profiles and distribution
  - [ ] Add managed Fast (Tiny), Balanced (Small) and High Quality (Base+)
        profiles only after measurements justify them.
  - [ ] Pin revisions and SHA-256 hashes; install atomically and support removal.
  - [ ] Add graceful WebGPU/FP16/model-absence fallbacks and Preferences UI.
  - [ ] Complete license notices and reproducible artifact provenance.
  - [ ] Keep SAM 3 experimental until its concrete ONNX license and provenance
        are confirmed.
  - Acceptance: documents never depend on a locally installed model and corrupt,
    incomplete or unavailable artifacts fail safely.
