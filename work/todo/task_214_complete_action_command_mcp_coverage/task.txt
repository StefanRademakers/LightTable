Task 214 - Complete user-action, Actions and MCP capability program

Status
======

Active program owner. The child tasks below are controlled, evidence-bearing
steps toward this outcome; splitting the work is not itself progress and does
not reduce the final acceptance bar.

Goal
====

Make every meaningful LightTable artist operation available through one typed,
categorized semantic capability architecture. Normal UI, Actions, Agent Access
and MCP must use the same application owners, while queries, gestures, tasks,
events and artifacts retain the execution semantics appropriate to their work.

The integrated result must let an agent inspect and construct a representative
editable composition, evaluate its real rendered output, correct it and leave
understandable reversible work—without automating private UI state.

Parent product goal
===================

[`architecture/goals/AGENT_NATIVE_CREATIVE_RUNTIME_TARGET.md`](../../../architecture/goals/AGENT_NATIVE_CREATIVE_RUNTIME_TARGET.md)

Program rules
=============

- Optimize for the complete product outcome, not small tasks, command counts
  or quick checkmarks.
- Use controlled vertical steps because they expose wrong assumptions early;
  preserve good proven behavior and revise the route when evidence changes.
- A child task is complete only when its representative real flow passes. Its
  completion never implies this program is complete.
- UI, Actions and MCP never receive parallel mutation implementations.
- Continuous interaction remains a bounded preview/commit transaction; it is
  not forced through one remote call per sample.
- Remote admission remains explicit even when local semantic coverage exists.
- Current, partial and target capability must remain visibly separated.

Integrated execution sequence
=============================

The sequence is dependency-aware, not a rigid waterfall. Categories may move
vertically through multiple steps when that produces earlier product evidence.

1. **Coverage and ownership truth (Task 214 workstream).**
   Inventory every operation surface, execution owner and unexplained gap.
2. **Shared contracts and examples ([Task 215](../task_215_shared_command_schemas_and_examples/task.txt)).**
   Establish machine-readable parameters/results and executable usage examples.
3. **Interactive execution semantics ([Task 216](../../done/task_216_semantic_gesture_commit_and_performance/task.txt)).**
   Preserve slider/transform/paint responsiveness through bounded commits.
4. **Equivalent-route proof ([Task 217](../../done/task_217_ui_actions_mcp_equivalence_harness/task.txt)).**
   Compare UI, Actions and real MCP state, history and rendered results.
5. **Agent observation loop ([Task 218](../../done/task_218_agent_observation_preview_and_events/task.txt)).**
   Add bounded structure, revision-bound preview and useful events.
6. **Durable Actions workflows ([Task 219](../task_219_durable_actions_workflows/task.txt)).**
   Make recorded workflows editable, persistent, task-aware and inspectable.
7. **Reviewed remote admission ([Task 220](../task_220_reviewed_mcp_capability_admission/task.txt)).**
   Expose proven categories with explicit permissions and remote evidence.
8. **Close semantic capability gaps ([Task 221](../task_221_close_semantic_capability_gaps/task.txt)).**
   Implement the missing artist categories through existing application owners.

Coverage and ownership workstream
=================================

Inventory menus, shortcuts, toolbar/options, panels, dialogs, context menus,
layer rows, canvas gestures, project/assets and GenAI surfaces. Every row records
source, semantic intent, category, current execution owner, command/gesture/
query/host/presentation classification, Actions state, remote relevance and an
explicit reason for any exclusion.

The checked inventory must detect:

- user operations with no semantic owner or mapping;
- catalog capabilities without a verified executor/consumer;
- duplicate UI/Actions/MCP behavior;
- presentation allowlist entries without reason and owner;
- implementation gaps without a controlled category plan.

Existing foundation evidence
============================

- Generated categorized command catalog and local Commands browser.
- Checked inventory for 103 static editor-menu actions and four dynamic
  families; the current report still has 7 genuine menu gaps.
- Semantic routing for Image Size, canvas geometry, crop, rotate and flip.
- Bounded recorder/playback, per-step results and stable-ID rebinding.
- Shared top-level property discovery for Actions and MCP.
- The first modular shared input/result schema slices now drive generated local
  controls plus direct/batch validation for ten structural layer commands and
  all four semantic Text commands in the application and MCP routes; remaining
  command schemas are still open.
- Trusted UI/MCP/playback origin and playback recording isolation.
- Packaged Create Raster Layer -> Rename Layer playback proof.
- Layer structure, final geometric selection, single-layer affine transform
  and bounded Brush/Erase stroke verticals now share typed UI/Actions/MCP
  capabilities; this is partial category evidence, not program completion.
- Select All, Clear/Deselect and Invert now share `selection.modify` across the
  real menu/keyboard owner, Actions and admitted MCP execution. Geometric,
  Magic Wand and discrete/Feather selection recipes now also carry shared
  version-1 input/result schemas; raster masks and pointer samples stay local.
- Fourteen basic Grade controls now share `grade.setBasic` with explicit
  document/layer targets, final slider recording and packaged Actions replay;
  `grade.queryBasic` now reads those canonical values through authenticated
  packaged Agent Access without history/recording mutation. Non-basic groups
  remain open. Shared version-1 schemas now enforce the same range map used by
  the sliders and require a non-empty bounded patch.
- Native point-text creation and faux-bold/italic/underline formatting now use
  shared semantic owners. Packaged Actions records, binds, undoes and replays
  UI text creation/formatting; packaged Agent Access creates, formats and
  queries the editable flow-text state.
- Layer-mask add, remove, enable/disable and link state now share one explicit-
  target `layer.setMask` contract. Packaged Actions proves real Layer-menu
  recording/replay; packaged Agent Access proves background-layer execution
  without changing the artist's active layer. Its shared version-1 schema now
  permits only fields relevant to the selected operation; raster-layer creation
  likewise publishes a complete schema and must return a stable created ID.
- Rectangle, Ellipse, Triangle and Line toolbar gestures now publish one
  lossless `vector.create` only after commit. Geometry, transform, layer/element
  names, fill, stroke and opacity remain native and replayable; pointer previews
  never enter the command service.
- Native Pen authoring now publishes one lossless `vector.create` after an open
  or closed path commit, and resumed authoring publishes one `vector.update`.
  Anchors, Bezier handles, style and transform remain native; point placement,
  handle dragging and rubber-band previews remain local.
- Add/Delete/Convert Point and committed Direct Selection geometry edits now
  publish final `vector.update`/`vector.remove` operations. Hit testing,
  selection, marquees and pointer previews remain local and unrecorded.
- Native Gradient Fill creation and on-canvas axis edits now share bounded
  `vector.create`/`vector.update` operations, including layer role, opacity and
  blend mode. Raster-pixel gradients remain on their separate GPU owner.
- Native Warp now keeps frame-coalesced pointer/hold previews local and emits
  one bounded layer-source `warp.applyStroke` per completed gesture. Packaged
  Actions proves Push plus held Twirl undo/replay; packaged Agent Access proves
  direct execution and bounded editable-recipe query.
- Solid raster/mask Fill now uses one explicit-target `raster.fill` capability
  through the existing GPU transaction and reversible pixel-history owner.
  Actions, packaged Agent Access and the external MCP bridge are proven.
- Raster/mask pixel gradients now publish one final bounded paint through
  `raster.applyGradient`; pointer movement remains local and the GPU/history
  transaction is shared by UI, Actions and Agent/MCP.
- Dodge, Burn and Sponge now share the bounded final brush-stroke contract.
  Effective operator settings publish only after successful GPU/history commit;
  interactive dabs remain on the existing local frame scheduler.
- Clone Stamp and Healing Brush now use that same final-stroke boundary with an
  explicit document-relative source anchor. Source pixels, immutable GPU
  snapshots and live pointer updates remain inside the desktop renderer.
- Magic Wand now exposes one asynchronous sampled-selection recipe through UI,
  Actions and admitted Agent/MCP execution; generated masks remain GPU-local.
- Native Path Text creation now shares `text.create` across UI, Actions and
  Agent/MCP, with explicit path layer/element/contour references and editable
  start-offset, side, upright and direction state.
- The five discrete Edit > Transform rotate/flip actions now share contextual
  `transform.applyFixed` execution across UI, Actions and Agent/MCP. The
  existing transform session still owns selection pixels, masks, single layers,
  layer groups, pivots and undo; no pointer or preview samples cross the command
  boundary. Exact affine `layer.setTransform` and these contextual operations
  now also have shared version-1 input/result schemas proven through packaged
  Actions, UI/Actions/MCP equivalence and external MCP discovery/execution.
- The complete visible Image > Adjustments family now resolves once to an
  explicit `adjustment.create` placement and stable target ID. Local Grade /
  Curves / Lens Fx, attached adjustments and standalone adjustment layers reuse
  their existing document/history owners across UI, Actions and Agent/MCP.
- Merge, Flatten Group and Flatten Image now add shared version-1 schemas to
  their existing explicit-target GPU/history owners. Destructive requests stay
  bounded and return stable output-layer IDs for later Action/agent steps.
- Layer > Invert Colors now records and executes `raster.invert` with an
  explicit stable layer ID and pixels/mask channel through the existing GPU
  pixel-edit and undo owner. Its shared schema exposes exactly those fields.
- Confirmed Convert Text to Shape and Rasterize Text now record and execute as
  explicit stable-target commands. Both retain their layer ID; shape output is
  native vector geometry and raster output waits for a final text source before
  using the existing GPU pixel-history owner.
- Merge Down/Selected, Flatten Group and Flatten Image now resolve UI context to
  explicit targets and share their full-canvas compositor/history owners with
  Actions and Agent/MCP. Destructive automation waits for contributing text
  sources; Flatten Image retains its final Grade reset and undo restoration.
- Selection > Feather now uses bounded `selection.modify` parameters and the
  existing asynchronous GPU/selection-history owner across UI, Actions and MCP.
- Remove Background now shares explicit raster-layer/mask-mode parameters,
  lazy BEN2 inference, cancellation, stale-result rejection and one reversible
  GPU mask transaction across UI, Actions and MCP. Model progress is bounded
  before React and task/event publication so long downloads cannot flood the
  reconnect buffer.
- Auto Align now shares an explicit raster reference/target task across Apply,
  Actions and MCP. Begin/Cancel and compositor preview stay local; an exact
  revision preview is reused, while direct automation runs the same cancellable
  GPU analysis and commits through the existing geometry/history owner.
- Layer via Copy now shares one explicit raster-source command. Existing
  selection pixels stay renderer-local, the created raster has a stable result
  ID, and UI/Actions/MCP reuse the same GPU/document/history transaction.
- Concrete Actions now have bounded version-2 save/load/delete persistence,
  version-1 migration with per-step command-contract checks and active-document
  replay. A packaged restart proves this workflow without routing any
  interaction preview through storage.

Program definition of done
==========================

- Every meaningful artist operation is accounted for as command, bounded
  gesture, query, task/event, host action or justified non-automatable state.
- Supported operations use the same semantic owners from normal UI, Actions
  and admitted MCP routes.
- Shared schemas/examples describe actual runtime behavior and remain versioned.
- High-frequency interactions stay responsive and publish bounded history.
- Representative UI/Actions/MCP workflows produce equivalent editable state,
  history and rendered output, including failure/stale/cancel paths.
- An agent can inspect bounded structure and revision-bound previews, execute a
  representative editable artist workflow, observe publication and correct it.
- Actions can persist and replay useful workflows with stable bindings and
  understandable task/error outcomes.
- Every remotely advertised capability is permission-reviewed and proven
  through the real packaged desktop bridge; every withheld capability has an
  explicit reason.
- Web/desktop/boundary/architecture verification passes and an owner reviews
  the representative product flow.

Non-goals
=========

- Declaring the program complete because all child task files moved to done.
- Exposing arbitrary state patches, React callbacks, DOM selectors or GPU
  objects.
- Automatically exposing every internal command remotely.
- Treating counts, schemas, test volume or one visual score as the outcome.
- Delivering headless execution, branching, teach mode or autonomous flat-
  reference reconstruction inside this program unless separately authorized.
