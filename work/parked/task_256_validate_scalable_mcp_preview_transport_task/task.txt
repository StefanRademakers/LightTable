Task 256 - Validate scalable MCP preview transport

Status
======

Parked until the local observation loop and representative creative-agent
workflow provide real traffic to measure. Hetzner Object Storage is a candidate,
not an approved production dependency.

Goal
====

Prove a thin-relay, ephemeral image-plane design that keeps creative processing
local and remains affordable and recoverable at large user counts without
changing the semantic command/query/event architecture.

Parent goal and source
======================

- [`Agent-native creative runtime target`](../../../architecture/goals/AGENT_NATIVE_CREATIVE_RUNTIME_TARGET.md)
- [`Expanded MCP future usage brief`](../../../architecture/goals/mcp_future_usage_target_v3.md)
- [`Task 218`](../../todo/task_218_agent_observation_preview_and_events/task.txt)

Activation gates
================

- A representative agent workflow can produce measured sessions with 20-100
  deliberate whole/region/layer inspections.
- Current inline artifact transport has recorded size, latency, retry and
  session-volume baselines.
- A remote deployment requirement exists; local/private MCP must not be made
  dependent on cloud storage merely to run the experiment.

Checklist
=========

- [ ] Define a provider-neutral `EphemeralObjectStore` boundary and threat
      model without routing document execution or AI reasoning into the relay.
- [ ] Prototype presigned PUT/GET and explicit DELETE against the selected
      Hetzner region; verify CORS, metadata, authorization failure, concurrency,
      abort behavior and actual MCP-client reachability.
- [ ] Verify supported lifecycle rules and incomplete multipart cleanup rather
      than assuming AWS S3 feature parity.
- [ ] Enforce session scope, explicit `expiresAt`, short TTL, disabled versioning,
      redacted logs and two-layer cleanup with orphan/leak fault injection.
- [ ] Measure thumbnail/working/inspect WebP and required PNG cases across
      20-100-look creative sessions: count, bytes, latency, retries and relay
      traffic.
- [ ] Model request, storage-hour and transfer cost for light/normal/heavy usage
      at 1,000, 10,000 and 100,000 monthly active users.
- [ ] Compare inline MCP image content, direct temporary object transfer and at
      least one alternative provider using measured results.
- [ ] Record an ADR approving or rejecting the provider/design; do not promote
      Hetzner, retention durations or cost claims before these gates pass.

Non-goals
=========

- Centralizing LightTable rendering, project storage or agent reasoning.
- Uploading pixels for state that queries can express structurally.
- Replacing the current local artifact path before a remote need is proven.
