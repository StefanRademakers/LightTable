# Task 146 - Bounded derived document-resource residency

Status: parked until multi-document memory measurements demonstrate pressure
that the existing active/warm/cold resource policies do not already control.

## Current premise

LightTable has one persistent editor/canvas runtime, not one mounted React
editor per document. Canonical document sessions, history and source resources
are application-owned and survive view/renderer rebinding. Inactive documents
do not require a second editor or render loop. Derived renderer resources are
disposable and must never become document authority.

The previous version of this task was based on the removed per-document editor
architecture. Do not restore that model, prewarm hidden canvases or make React
mount state part of document persistence.

## Activation gate

Reactivate only after a packaged multi-document profile records, per document:

- canonical CPU/resource bytes;
- active and retained GPU bytes;
- background submissions while inactive;
- tab-switch latency for warm, cold and rebuilt resources;
- close-time release and device-loss recovery;
- memory behavior under an explicit pressure scenario.

The evidence must identify a user-visible memory or latency problem. A guessed
document-count cap is not sufficient.

## Intended architecture

- Keep canonical document data and history independent from view and GPU
  lifetime.
- Reuse the existing active/warm/cold/evicted vocabulary for derived raster,
  vector, text, mask, preview and analysis resources where it fits.
- Budget textures and derived caches independently from canonical resources.
- Prefer least-recently-used eviction of rebuildable inactive resources;
  active resources are not evicted opportunistically.
- Rebind one active renderer to the selected canonical document. Rebuild only
  missing derived state and never reopen or mutate the source as restoration.
- Cancel or settle an active gesture deterministically before document switch,
  close or eviction.
- Keep thumbnails/previews bounded and derived; they cannot substitute for
  canonical pixels or editable resources.

## Acceptance

- Repeated warm/cold tab switches preserve exact document revision, layer tree,
  history and representative rendered pixels.
- Workspace/panel changes do not affect document or resource residency.
- Inactive documents submit no presentation or processing work.
- Resource eviction and rehydration have explicit telemetry and bounded
  latency, with no listener, heap or GPU growth across repeated cycles.
- Closing one document releases only its canonical and derived resources.
- Device loss rebuilds derived resources from canonical authority.
- Packaged Windows and macOS evidence passes before enabling a default policy.
