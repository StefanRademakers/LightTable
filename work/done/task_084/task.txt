# Task 084 — bounded autosave recovery journal (P0)

Priority: P0. Depends on Task 083. Expected effort: 8–12 focused hours.

## Objective

Persist recoverable canonical edits without serializing GPU caches or blocking
interaction. Journals must be bounded, private, versioned and provably unable
to corrupt normal save/open behavior.

## Required work

- Before implementation, research and cite primary sources for Photoshop-style
  background recovery, Electron private application storage and atomic host
  writes, browser OPFS/quota behavior and recovery crash-loop failure modes.
  Record the chosen design and rejected alternatives in a persistence ADR.
- Define a versioned recovery record: document/session identity, source
  fingerprint, canonical revision, save-state ID, manifest/assets and checksum.
- Choose snapshot-plus-bounded-delta or snapshot-only behavior from measured
  serialization/write cost; document the decision.
- Schedule only after semantic commits with debounce/max-delay and newest-work
  supersession. No pointer-move, viewport, overlay or background timer churn.
- Store per-installation recovery data in a host capability; browser storage
  must use quota/error reporting and Electron must use private app data.
- Encrypt or avoid sensitive metadata where platform facilities permit; never
  upload journals.
- Bound document count, age and bytes with deterministic pruning.
- Delete or supersede records only after a verified native save or explicit
  discard; retain them after crashes and failed saves.
- Isolate malformed/old records and expose migration/rejection reasons.

## UI exposure

Add only a subtle recoverability/status indicator to the existing document
status surface. The recovery chooser belongs to Task 085.

## Verification and completion

- Fake-clock and fault-injection tests for debounce, supersession, quota,
  pruning, corrupt records, close and crash-like termination.
- Measure serialization time, main-thread long tasks, journal size and idle
  writes on small and EHS-396-class documents.
- Prove inactive unchanged documents perform no recurring work.
- Run shared typechecks/tests and production builds; update architecture,
  commit independently and move to done.

## Completion evidence (2026-08-06)

- Added the versioned private recovery contract, Electron atomic recovery
  store, browser OPFS adapter and metadata/checksum validation.
- Recovery is driven only by semantic history snapshots with a 5 s debounce,
  30 s maximum age, single-writer/newest-only handoff and no idle polling.
- Verified cleanup after committed Save and explicit discard; failed/canceled
  saves retain their checkpoint.
- Fake-clock, quota, pruning, corrupt-record, checksum, close and roundtrip
  coverage passes (20 focused recovery tests across app and desktop suites).
- Full app suite: 315 files / 1683 tests. Desktop suite: 5 files / 24 tests.
  App/desktop typechecks, boundary verification, web production build and
  packaged Electron build pass.
- Packaged TextTest checkpoint: 466 KiB, 325.3-359.5 ms prepare and 19.7-20.5
  ms atomic persistence; zero page errors. Verified Save removed all recovery
  generations only after commit.
- Packaged EHS-396: zero post-import >50 ms main-thread tasks during recovery,
  but the 178 MB snapshot did not finish within 150 s and published no partial
  file. This measured large-document baseline is explicitly assigned to Task
  107's content-addressed/delta optimization gate; it is not accepted as a
  release-performance target.
- Design, primary sources, privacy rules, rejected alternatives and measured
  evidence are recorded in `architecture/contracts/RECOVERY_PERSISTENCE_ADR.md`.
