Completed evidence (2026-08-20)
===============================

- `npm run smoke:desktop:duplicate-image` passed against the packaged desktop
  and an independently authenticated Streamable HTTP MCP client.
- The source contains native raster, vector and editable text layers plus a
  document Grade. Image > Duplicate recorded `document.duplicate` followed by
  `layer.createRaster` in the fresh result document.
- Actions replay remapped that recorded result to its new duplicate; external
  MCP used the returned document ID explicitly. UI, Actions and MCP ended with
  equal editable layer/vector/text state and one independent history edit.
- UI versus Actions and UI versus MCP both measured RMSE 0, maximum channel
  delta 0 and changed-pixel ratio 0.
- Source canonical revision, history, dirty state and complete normalized
  structure stayed unchanged across all three forks and later edits.
- Every duplicate starts at history depth zero with disjoint document/layer
  identities. A prior broad string remapper was corrected so user content that
  merely equals an internal ID is no longer rewritten; only explicit identity
  fields are remapped.
- Private path/flatten fields and stale source revisions are rejected without a
  fork or source mutation.

Constraints
===========

- No source path, overwrite target, flattened-only switch or pixel payload is
  accepted by the public command.
- Duplication is a workspace fork, not an undo entry in the source document.
- The duplicate is a new unsaved document with fresh document/layer/runtime
  identities and an empty history baseline.
- No raw pointer/paint/slider path is involved.
- Experimental Face Warp remains explicitly withheld; completing this task
  leaves it as the only legacy-schema command for an honest reason.
