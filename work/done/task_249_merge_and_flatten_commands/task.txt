Task 249 - Explicit merge and flatten commands

Goal
====

Expose Merge Down/Selected, Flatten Group and Flatten Image through explicit
stable-target commands shared by UI, Actions and reviewed MCP execution while
retaining the existing full-canvas GPU and history owner.

Out of scope
============

- Adding new merge modes or changing flatten appearance.
- Treating host confirmation UI as part of the semantic mutation.

Result and evidence
===================

- Normal Merge Down resolves its active sibling pair once; multi-selection
  resolves to explicit IDs. Group and image flatten carry no hidden target.
- The command service normalizes merge order through the canonical contiguous-
  sibling plan before execution and rejects duplicate, non-contiguous, empty or
  expanded destructive requests.
- The previously strict application parsers now also have shared version-1
  input/result schemas. Actions and MCP discovery expose only explicit bounded
  IDs and stable output IDs; expanded Flatten Image options fail pre-mutation.
- Automation yields one editor frame and waits only for contributing visible
  text sources before entering the existing synchronous GPU transaction.
- Focused service tests prove Actions record/replay for merge and both flatten
  scopes. Existing owner tests retain the Grade-reset/undo contract.
- The packaged external MCP smoke creates two filled raster layers, merges them
  to a new returned ID, flattens the complete document and verifies exactly one
  raster layer with the returned final ID. Preview/native/PSD export behavior is
  exercised before the deliberate destructive final proof.
- Menu coverage is 103 inventoried actions with 13 genuine semantic gaps.
