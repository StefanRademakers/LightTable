Task 265 - Complete Image Size and document geometry across UI, Actions and MCP

Goal
Promote the existing canonical Image Size and Canvas/Crop/Rotate/Flip owners to
closed shared capabilities that normal UI, Actions and reviewed MCP execution
can use with equivalent document, history and rendered results.

Checklist
- [x] Define modular closed v1 input/result schemas and representative examples for `document.resizeImage` and `document.applyGeometry`.
- [x] Preserve exact resampling, layered semantics, selection/mask projection, guides, GPU transfer and undo owners.
- [x] Return actual post-commit canvas dimensions instead of merely echoing requested values.
- [x] Reject private UI state, unsafe dimensions, crop bounds and numerically unstable arbitrary rotations before mutation.
- [x] Render both commands as executable schema-driven Actions forms.
- [x] Admit both commands to Agent Access and generic MCP execution with explicit destructive-edit documentation.
- [x] Add contract, command-service, Actions and MCP rejection/equivalence tests.
- [x] Prove normal UI, Actions replay and external MCP on packaged Electron; retain detailed layered Image Size and document-geometry smokes.
- [x] Update coverage/program documentation and run full repository gates.

Performance constraints
- Image Size and document geometry remain one discrete commit each.
- No pointer, crop-gizmo, slider preview, GPU transfer loop or renderer callback enters MCP/schema validation.
- Actions records final normalized parameters only after the existing UI commit succeeds.

Non-goals
- Remote simulation of the Crop gizmo or arbitrary-rotation dialog.
- Changing resampling algorithms or geometry projection math.
- Adding projective transforms.
