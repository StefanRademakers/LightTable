# Task 101 — unsupported-feature and recovery UX (P2)

Priority: P2. Depends on Tasks 090–094. Expected effort: 5–9 focused hours.

## Objective

Turn import/export limitations into understandable, actionable recovery instead
of debug-only warnings, silent rasterization or disabled controls.

## Required work

- Normalize capability findings by document/layer/feature/severity and action:
  exact, approximated, preview-backed, missing asset/font, export-blocking.
- Present one compact document summary with navigation to affected layers.
- Provide only safe actions: keep preview, replace font, rasterize explicit copy,
  remove unsupported effect, cancel export or export flattened.
- Show what edit will invalidate a retained preview before it happens.
- Preserve original metadata/source until an explicit destructive decision.
- Keep diagnostics copyable and useful without leaking full local paths/content.

## UI exposure

Use a normal inspector/start/import-report surface, layer badges and existing
dialogs/buttons. Do not flood the Layers tree with dormant or non-actionable rows.

## Verification and completion

- PSD/PDF fixtures for every status/action and cancel/undo/save/reopen.
- No supported document shows warnings; no unsupported case disappears silently.
- Keyboard/accessibility and compact-panel tests.
- Export preflight and retained-preview regressions pass; docs, commit, move.
